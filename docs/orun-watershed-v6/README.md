# Orun · Watersheds and habitats v6

保留既有山体与地形方块，在最终高度场上重建共享河网、湿润生境和 200 米方块云。

## 结果

- 八组相连流域，每组二十个新增泉源；另保留二十三个原有泉源和三个地图河流入口。
- 127 个汇合节点、313 段共享河道。1622 个落差大于 12 米的跌水段是沿河岩阶的统计，不代表 1622 条独立河流。
- 226 个浅积水或闭洼潭单元；深闭洼不被强行打通。水体具有蓝色表面、跌水厚度及邻近喷雾。
- 全域 128 米抽样、按连续地表面积加权，39.31% 的区域有至少 10% 的植被颜色贡献；平均植被贡献为 17.43%。矿物绿色没有计入。低地、山腰和高原带绿面积分别约 33.0%、44.4%、44.9%；低地水边更深，高原主要为浅草苔。
- 默认云使用 200 米立方体，约 13.7 万逻辑体元、8.8 万渲染三角面。主体为横向云带，连续厚度最多三层；不使用体积光线步进。

## 使用与复现

导入 `parameters.json` 使用本轮默认参数。`ecologyMode=0` 使用旧水系和 100 米云算法；旧参数文件自动进入这个兼容模式。`materialMode=0` 切回原有地表配色；`paletteStyle=0` 恢复灰蓝岩土色样。

泉水与季节性补给、坡面保水、含水层渗水会重算水文或生态，保留旧画面并允许取消。地形侵蚀历史补给仍是地形参数，和本轮生境供水分开。八族岩土调色只更新颜色贡献。

离线顺序：`build-orun-water.cjs` → `build-orun-ecology.cjs`。前者只读取最终高度，后者按固定 16 米基元积分覆盖与颜色。输入索引仅保存文件引用，不重复写入运行时数组。所有二进制数据按 32 MiB 分块并带 SHA-256。

## 验证

- 新增八项测试通过：无供水平地、坡向旋转、支流合并与收支、孤立地块、海拔植被、旧参数兼容、水体厚度和每面颜色、200 米云网格。
- 实景河网所有细分段无逆坡、无穿地；十五处带草样本的 64 米父面与十六个 16 米子面平均颜色最大线性误差约 9.81e-9。
- 固定平原机位：137710 个地形柱、801166 个地形三角面。修改前后位置、法线和索引哈希均为 `4ad4650db7f332e71cb5e46c04fb2495d5f43761d0ad3b2705591a491f795b27`。
- 最终高度 SHA-256：`9a32558b6902a11ed4d2b5013ce5b6d3e4910ba5a348f97b0335da5df5d8dcea`。
- 源站浏览器检查没有脚本错误或缺失资源。首次加载约 60.7 秒（输入索引清理前）；默认和最大云量的采样帧时间均约 16.6 毫秒。生态预积分约 214 秒、128.4 MB；后台河网约八秒。性能是当前机器与固定机位的测量值。
- `visuals` 保存自然光、无光照、河网、季节性湿度、渗水和植被图。`before` 保存上一版预览中的相同平原、高原、临墙与全景机位，`comparison.html` 可直接查看。新的 The Weeps 机位指向新河网的代表跌水，不用于同机位前后比较。

## 模型边界

这是有收支记录的程序化水文与生境模型。泉群使用共享流域预算；本地补给按 0.16 米/年估算，额外水量明确记录为外部含水层输入，未当成实测降雨。闭洼潭使用补给、蒸发与入渗平衡；浅溢流湖面的蒸发目前记录为需求诊断，未执行长期湖泊演化。植被场表示稳定气候与供水下的外观，云移动不会即时改变草苔。

当前范围内主河最终多进入闭洼，不能据此声称已把整张世界地图的河流贯通。山体、湖盆和地形侵蚀历史没有被本轮重写。
