# Atheria · terrace 拆解与近立方体房屋

算法版本：terrace-volume-v5。原基线、保护建筑、地形和人工场景保持；默认滑条数值保持。

## 现在的变化

- terrace 从外围单侧、两侧或四侧试切，保留含最高点的连通核心和至少两个高度层次。拆解强度 t=max(0,2×split−1)，外围占地目标为 15%+30%×t，拉满为45%。现有 terrace 优先安排拆出的房块，空地不足时记录部分完成或无法安置。
- 小房块的宽＝深＝∛(V÷n÷r)，高＝r×宽，r为稳定编号确定的1–1.35。宽深不超过24米，每组最多64个搬移块；保留颜色、朝向和来源，按实际新占地检查碰撞、承托、距离和田地15%上限。
- 不再额外降低15%高度。V取尺寸和高度调节后的来源体积；原地核心保持调节后的高度。历史基线中已有的降低保持原样。
- 拆解后的核心及新块在四级远近细节中保持实际尺寸，退让处恢复地面。面板显示达到目标、部分完成、无法安置和实际拆出比例。
- 浏览器和导出统一立方根精度；旧方案明确提示按新版重新计算；预计算缓存核对算法版本、基线、参数及种子。

## 实际结果与限制

默认 split=0.92：160组 terrace 中134组发生拆解，较旧版72组增加62组；实际拆出来源占地的中位数由约4.9%提高到约10%。其中15组达到40.2%的目标，119组部分完成，25组无法安置，另1组受保护。全城所有类型合计2613组拆解。空地充足的固定测试达到45%，真实屋群仍受核心结构及空地容量限制。提高全城目标时，各屋群会争用同一批安全空地，实际完成程度不保证逐组单调增加。

全城默认计算约10.9秒；提前排除过小或已满的落点后，与优化前的房块、切口和落点逐项一致。

15项专项检查、96项既有控制检查，以及浏览器、四级细节、方案保存载入、压缩网页和独立导出检查通过。639份导出网格改变，17,747个最细建筑体块核验，导出结果与预览计算一致。
